## 1. Project Overview

**Planner** is a standalone Windows desktop application for personal daily productivity. It replaces the need for multiple apps by combining a weekly schedule grid, monthly calendar, to-do list, reading tracker, daily notes, and usage statistics — all in one offline-first tool.

**Key principles:**
- 100% local — no cloud, no accounts, no telemetry
- Zero-friction — double-click to open, auto-save on every change
- Bilingual — English and Serbian (srpski) language support
- Persistent — remembers your last tab, scroll position, and all data between sessions
- Themeable — dark and light mode, preference saved across sessions

## 2. Tech Stack

| Layer | Technology | Purpose |
|---|---|---|
| Desktop shell | Electron 33 | Native Windows app wrapper |
| Build tool | electron-vite 2 + Vite 5 | Fast builds, HMR in dev |
| UI framework | React 18 + TypeScript | Component-based UI |
| Styling | Tailwind CSS v3 + CSS custom properties | Dark/light theme design system |
| Charts | Recharts | Statistics visualization |
| State management | Zustand | Lightweight app state |
| Database | node-sqlite3-wasm | SQLite via WebAssembly (no native compilation) |
| Internationalization | react-i18next | EN/SR language switching |
| Packaging | electron-builder | NSIS `.exe` installer for Windows |

### Why `node-sqlite3-wasm` instead of `better-sqlite3`?

`better-sqlite3` requires Microsoft Visual Studio Build Tools to compile native C++ bindings. `node-sqlite3-wasm` is compiled to WebAssembly and works without any native toolchain, making setup completely frictionless. The API is nearly identical.

## 3. Architecture

### Electron Process Model

```
┌─────────────────────────────────────────┐
│           Main Process (Node.js)        │
│  ┌──────────────┐  ┌─────────────────┐  │
│  │  SQLite DB   │  │   IPC Handlers  │  │
│  │  (WAL mode)  │  │  (ipcMain)      │  │
│  └──────────────┘  └─────────────────┘  │
│         ↑ stored at %APPDATA%\Planner\  │
│                       planner.db        │
└──────────────────────┬──────────────────┘
                       │ contextBridge (IPC)
┌──────────────────────▼──────────────────┐
│         Renderer Process (React)        │
│  ┌──────────────┐  ┌─────────────────┐  │
│  │ Zustand      │  │  Tab Components  │  │
│  │ Stores       │  │  (5 tabs)        │  │
│  └──────────────┘  └─────────────────┘  │
└─────────────────────────────────────────┘
```

### Data Flow

```
User types activity
        ↓
SlotCell component (renderer)
        ↓
activityStore.upsertActivity()
        ↓
window.api.activities.upsert()   ← preload bridge
        ↓
ipcMain handler
        ↓
categorizeActivity()  ← keyword matching
        ↓
activities.ts → db.run(INSERT)
        ↓
Returns ActivityRow (with category info)
        ↓
Store updates React state → UI re-renders
```

### Window Configuration

- **Size:** 1280 × 800px initial, resizable, maximizable (min: 960 × 640px)
- **Theme:** Dark mode default, user-switchable to light mode
- **Menu:** Auto-hidden (no default Electron menu bar)
- **Context isolation:** Enabled (secure `contextBridge` preload)
- **Icon:** Custom planner-themed icon (generated by `scripts/gen-icon.mjs`)

## 5. Database Schema

**Location:** `%APPDATA%\Planner\planner.db` (created on first launch)

### Tables

#### `categories`
Stores activity categories with bilingual names and visual identifiers.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| name_en | TEXT | English display name |
| name_sr | TEXT | Serbian display name |
| icon | TEXT | Emoji icon |
| color | TEXT | Hex color for charts and blocks |
| is_default | INTEGER | 1 = built-in category, 0 = user-created |
| created_at | TEXT | ISO datetime |

#### `keywords`
Many-to-one with categories. Used for auto-categorization.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| category_id | INTEGER FK | → categories(id) ON DELETE CASCADE |
| keyword | TEXT | Lowercase keyword for matching |

#### `activities`
Individual time blocks on the weekly schedule grid.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| date | TEXT | YYYY-MM-DD |
| start_time | TEXT | HH:MM (30-min aligned, e.g. "09:00") |
| end_time | TEXT | HH:MM exclusive end (e.g. "10:30") |
| name | TEXT | Activity name as entered by user |
| category_id | INTEGER FK | → categories(id) (nullable) |
| is_event | INTEGER | 1 = created from calendar_events |
| event_id | INTEGER FK | → calendar_events(id) ON DELETE SET NULL |
| created_at | TEXT | ISO datetime |
| updated_at | TEXT | ISO datetime |

#### `calendar_events`
Events added from the Calendar tab.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| date | TEXT | YYYY-MM-DD |
| title | TEXT | Event title |
| note | TEXT | Optional note (nullable) |
| created_at | TEXT | ISO datetime |

#### `todos`
To-do list tasks, split into Daily and Long-term categories.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| title | TEXT | Task title |
| description | TEXT | Optional description (nullable) |
| due_date | TEXT | YYYY-MM-DD (nullable) |
| priority | TEXT | 'high' \| 'medium' \| 'low' |
| task_type | TEXT | 'daily' \| 'longterm' (default: 'daily') |
| completed | INTEGER | 0 = active, 1 = done |
| created_at | TEXT | ISO datetime |
| updated_at | TEXT | ISO datetime |

#### `books`
Reading list / book tracker.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| title | TEXT | Book title |
| author | TEXT | Author name (nullable) |
| total_pages | INTEGER | Total page count |
| pages_read | INTEGER | Pages read so far |
| completed | INTEGER | 0 = reading, 1 = finished |
| created_at | TEXT | ISO datetime |
| updated_at | TEXT | ISO datetime |

#### `daily_notes`
One journal entry per calendar day.

| Column | Type | Description |
|---|---|---|
| id | INTEGER PK | Auto-increment |
| date | TEXT | YYYY-MM-DD (UNIQUE) |
| content | TEXT | Note text (plain text) |
| created_at | TEXT | ISO datetime |
| updated_at | TEXT | ISO datetime |

#### `settings`
Key-value store for app preferences.

| Column | Type | Description |
|---|---|---|
| key | TEXT PK | Setting name |
| value | TEXT | Setting value |

**Default settings:**
| key | default value | Description |
|---|---|---|
| language | en | UI language: 'en' or 'sr' |
| last_tab | schedule | Last active tab ID |
| theme | dark | UI theme: 'dark' or 'light' |

### Entity Relationships

```
categories ──< keywords          (1 category → many keywords)
categories ──< activities        (1 category → many activities)
calendar_events ──< activities   (1 event → 0-1 linked activity)
```

## 6. Running in Development

### Prerequisites

- Node.js 20+ (tested on v24)
- npm

> **Note:** No Visual Studio Build Tools are required. The app uses `node-sqlite3-wasm` (pure WebAssembly SQLite) instead of native `better-sqlite3`.

### Steps

```bash
# 1. Clone / navigate to project
cd C:\projekti\artok

# 2. Install dependencies
npm install

# 3. Download Electron binary (if not already done)
node node_modules/electron/install.js

# 4. (Optional) Regenerate app icon
npm run gen-icon

# 5. Start dev mode (opens Electron window with HMR)
npm run dev
```

The app opens in a 1280×800 window (resizable). Changes to renderer code hot-reload instantly. Changes to main process code require a restart (`Ctrl+C` then `npm run dev`).

**Dev database location:** `%APPDATA%\Planner\planner.db`

## 7. Building the Windows Installer (.exe)

### Prerequisites

- Node.js 20+
- Internet connection (downloads Electron binary and NSIS tools on first build)
- No Visual Studio Build Tools needed

### Build Command

```bash
# Regenerate icon + build vite bundles + create NSIS installer
CSC_IDENTITY_AUTO_DISCOVERY=false npm run build:win
```

The `CSC_IDENTITY_AUTO_DISCOVERY=false` env var disables code signing (not needed for personal use).

### Output

```
dist/
├── Planner-Setup-1.0.0.exe     ← Installer (~85MB)
├── Planner-Setup-1.0.0.exe.blockmap
└── win-unpacked/               ← Unpackaged app (for testing)
    └── Planner.exe
```

### Installing

1. Run `Planner-Setup-1.0.0.exe`
2. Choose installation directory (optional)
3. Install → app opens and creates a desktop shortcut
4. Database is created at `%APPDATA%\Planner\planner.db` on first launch

## 8. Feature Guide

### Window

- **Resizable:** Drag any edge or corner to resize; minimum 960×640px
- **Maximizable:** Double-click title bar or use the maximize button
- **Movable:** Drag the title bar to reposition

### Tab 1 — Weekly Schedule

- **Navigate weeks:** Use ← → arrows above the grid
- **Add activity:** Click and drag across empty cells to define the time range, then type the activity name and press Enter
- **Change category:** Right-click any activity block → hover "Change Category →" → select from submenu
- **Delete activity:** Right-click any activity block → Delete activity
- **Column colors:** Even/odd day columns have subtly different shades for easy visual separation
- **Row colors:** Even/odd 30-min rows have subtly different shades for easy vertical tracking
- **Today highlight:** Current day column has a distinct indigo tint; current hour row is highlighted
- **Auto-categorization:** Activity name is matched against keywords; category assigned automatically

### Tab 2 — Calendar

- **Navigate months/years:** Use ← → arrows
- **Add event:** Click any day → fill in title + optional note → Save
- **Edit/delete event:** Click a day with an existing event → edit or delete
- **Schedule sync:** When you add an event, it automatically appears in Tab 1 on the correct date

### Tab 3 — Statistics

- **Change period:** Toggle between Day / Week / Month
- **Charts:** Donut chart shows category distribution; bar chart shows hours per category
- **Summary cards:** Total hours logged, top category, most active day, remaining hours in period
- **Remaining hours:** Calculated as `(days remaining × 17h) − hours already logged`

### Tab 4 — To-Do List & Books

**Tasks section (two sub-sections):**

- **📅 Daily Tasks** — things to do today or this week
  - Add with the "Add" button in the Daily section header
- **🎯 Long-term Goals** — future projects, ongoing objectives
  - Add with the "Add" button in the Long-term section header
- Both sections share the same mechanics: checkbox completion, priority colors, due dates, inline editing
- When adding or editing a task, switch between Daily/Long-term using the segment toggle
- **Filter:** All / Active / Completed applies to both sections simultaneously

**Books section:**
- Switch to Books using the section toggle
- Track reading progress with page counter (+1, +10 or direct input)
- Mark a book as completed with the circle button
- Progress bar shows % read

### Tab 5 — Daily Notes

- Opens to today's date
- Type freely — auto-saved after 800ms of inactivity
- Navigate past days using ← → arrows (future dates blocked)
- Dates with existing notes shown as quick-access buttons at the bottom

### Bottom Bar (persistent)

- Visible across all tabs
- Shows upcoming calendar events as **sticky note cards** for the next 60 days
- Each card displays: the date label (Today / Tomorrow / date) and event title
- Color coding by urgency: red (today), amber (within 2 days), indigo (within 7 days), dim (further out)
- **Click any card** to navigate to Tab 2 (Calendar) and open that date
- Scrollable if many events exist

### Header Controls

- **Clock:** Live time and date in the centre
- **EN / SR:** Language toggle — switches all labels instantly, preference saved
- **☀️ / 🌙:** Dark/light mode toggle — switches entire app theme, preference saved
- **⚙️ Settings:** Slide-in panel for categories, export/import

### Settings Panel (⚙️ gear icon)

- **Language:** Switch between English and Serbian instantly (preference saved)
- **Categories:** Expand any category to edit name, icon, color, keywords
- **Add category:** Create custom categories with any emoji icon and hex color
- **Export:** Save all data to a JSON file (choose location)
- **Import:** Load data from a JSON backup (overwrites current data after confirmation)

### Right-Click Context Menu (Tab 1 activities)

The context menu uses a **cascading design**:
- Top entry shows the activity name (read-only label)
- **"Change Category →"** — hover to expand a submenu listing all categories; current category is checkmarked
- **"Delete activity"** — removes the activity from the schedule

## 9. UI/UX Design Decisions

### Color Theme System

Colors are defined as CSS custom properties (`--c-base`, `--c-surface`, etc.) in `globals.css`. The `.light` class on the root element swaps all variables simultaneously. All components use `var(--c-...)` references rather than hardcoded hex values.

**Dark theme (default):**
```
--c-base:    #0f1117   (main background)
--c-surface: #1a1d27   (panels, cards)
--c-element: #242736   (inputs, buttons)
--c-border:  #2d3142   (borders)
--c-text:    #f1f5f9   (primary text)
```

**Light theme:**
```
--c-base:    #f8fafc
--c-surface: #f1f5f9
--c-element: #e2e8f0
--c-border:  #cbd5e1
--c-text:    #0f172a
```

### Schedule Grid Visual Design

- **Column alternating:** Even/odd day columns differ by ~1.2–1.8% opacity overlay — subtle but visible
- **Row alternating:** Even/odd 30-min rows differ by ~1.8–2.5% opacity overlay
- **Today column:** Indigo tint (~8–10% opacity) applied to entire column including header
- **Current time row:** Stronger indigo tint (~12–16% opacity) + a solid 2px indigo line at top of slot

### To-Do Split Design

- Two sections shown in one scrollable list with a divider
- Each section has its own "+ Add" button that pre-selects the correct task type
- The task type can be changed at any time via the toggle in the edit form
- `task_type = 'daily'` is the default for all existing tasks (migration applies `DEFAULT 'daily'` retroactively)

### Bottom Bar

- Fixed 52px height, always visible
- Horizontally scrollable (hidden scrollbar) when many events exist
- Urgency color coding based on days until the event
- Empty state shows "📅 No upcoming events" at 44px height

### App Icon

Generated programmatically by `scripts/gen-icon.mjs` using only Node.js built-ins (no canvas library). The icon features:
- Rounded indigo background
- White calendar header bar
- Grid of date cells (3×3), center cell highlighted (today indicator)
- Green checkmark badge in the bottom-right corner

Sizes: 256×256, 64×64, 48×48, 32×32, 16×16 — all embedded in the ICO file as separate PNG images.

## 10. Developer Guide — Adding New Features

### Adding a New IPC Channel

1. **Main process** (`src/main/ipc/index.ts`): Add `ipcMain.handle('myfeature:action', ...)`
2. **Preload** (`src/preload/index.ts`): Add `myfeature: { action: () => ipcRenderer.invoke('myfeature:action') }`
3. **Preload types** (`src/preload/index.d.ts`): Add TypeScript signature to `window.api`
4. **Renderer**: Call `window.api.myfeature.action()` from any component

### Adding a New Database Table

1. Add `CREATE TABLE IF NOT EXISTS ...` to `src/main/db/schema.ts` inside `runMigrations()`
2. Create a new query module `src/main/db/myfeature.ts`
3. Add IPC handlers in `src/main/ipc/index.ts`
4. Add to `data:export` and `data:import` handlers for backup support
5. Create a Zustand store in `src/renderer/src/stores/myfeatureStore.ts`
6. Add IPC bridge to preload

### Changing the Color Theme

Edit `src/renderer/src/styles/globals.css` — modify CSS custom properties in `:root` (dark) and `.light` blocks. Do **not** hardcode hex colors in component files; always use `var(--c-...)` references so both themes work.

### Adding a Language

1. Create `src/renderer/src/i18n/[lang].json` (copy from `en.json`)
2. Add to `i18n/index.ts` resources map
3. Add button to `Header.tsx` language toggle
4. Add button to `SettingsPanel.tsx` language section

### Regenerating the App Icon

```bash
npm run gen-icon
```

This overwrites `resources/icon.png` and `resources/icon.ico`. Modify `scripts/gen-icon.mjs` to change the design.

## 11. Known Limitations & Future Ideas

### Current Limitations

| Area | Limitation |
|---|---|
| Weekly Schedule | No drag-to-move (only drag-to-create); overlapping activities not handled |
| Statistics | No trend/line chart over multiple weeks |
| Notes | Plain text only — no markdown rendering, no images |
| Categories | Keyword matching is substring-based (no fuzzy matching) |
| Books | No book cover art or ISBN lookup |
| Calendar | Cannot add recurring events |
| Bottom Bar | Shows only the first event per date (not multiple on same day) |
| Data | No iCloud/Google Calendar sync (by design) |
| Packaging | Code signing skipped — Windows SmartScreen may warn on first run; click "Run anyway" |

### Future Improvement Ideas

- **Drag-to-move activities** on the schedule grid
- **Recurring calendar events** (daily, weekly, monthly)
- **Trend line chart** in Statistics (e.g. sport hours per week, last 12 weeks)
- **Markdown rendering** in Daily Notes
- **Pomodoro timer** integrated with the schedule
- **Week overview summary** — end-of-week digest of what was accomplished
- **Keyboard shortcuts** for tab switching, adding tasks, etc.
- **Code signing** — obtain a certificate for no-warning installs
- **Auto-updater** — electron-updater for seamless version upgrades
